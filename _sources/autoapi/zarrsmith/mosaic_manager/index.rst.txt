.. py:class:: Tile

   One acquired tile of a mosaic: a lazy ``(z, y, x)`` array and where it sits.

   Placement is a translation, after optional axis flips: the data is first
   mirrored along the axes where ``flip`` is true (e.g. the mirror image seen by an
   opposing camera), then ``origin`` is the position (in ``units``) of voxel
   ``[0, 0, 0]`` of the flipped data in the common sample frame and ``voxel_size``
   the voxel spacing. All tiles of a mosaic must use the same units and voxel size.

   Parameters
   ----------
   data
       Anything with ``shape``, ``dtype`` and numpy-style slicing that returns
       array data: an ``h5py.Dataset``, a dask or a numpy array. It is only
       read when a fusion needs it.
   origin, voxel_size
       ``(z, y, x)`` position of the first voxel and voxel spacing.
   channel
       Channel (dye) name. Tiles with the same name are fused into one output
       channel.
   group
       Optional label of tiles that should be merged among themselves first,
       e.g. ``"L"``/``"R"`` illumination side. Used by ``blend="sigmoid"`` and ``"midline"``.
   timepoint
       Index of the timepoint the tile belongs to (``0`` for a single timepoint).
       Tiles of one position at different timepoints are matched by
       :func:`series_keys`.
   attrs
       Free-form, reader specific metadata (stack, grid position, ...). ``stack``
       names the position of the tile, the same at every timepoint.
   units
       Units of ``origin`` and ``voxel_size``.
   field
       Name of the field (connected group of touching tiles) the tile belongs to,
       e.g. ``"field0"``. Set by :class:`~zarrsmith.mosaic_manager.MosaicManager` when
       the mosaic is loaded (see :func:`~zarrsmith.mosaic_manager.fields.label_fields`),
       unless the reader gives one.
   camera
       Optional name of the camera (detection view) the tile was taken with, e.g.
       ``"left"``/``"right"`` for the opposing cameras of a MuVi SPIM. Tiles of
       several cameras are fused as separate views, blended along their detection
       axis (see :func:`~zarrsmith.mosaic_manager.fuse_tiles`); ``attrs["detection_direction"]``
       (``(z, y, x)``, in the frame of ``origin``) says which side each camera images best.
   flip
       ``(z, y, x)`` axes along which the data is mirrored before it is placed.

.. py:class:: H5Array(path: str | pathlib.Path, dataset: str = 'Data', shape=None, dtype=None)

   Lazy, picklable view of one HDF5 dataset.

   The file is opened for every read, so the object holds no handle: it can be
   sent to worker processes (which is what lets :func:`~zarrsmith.mosaic_manager.fuse_tiles`
   read many tiles in parallel despite h5py's per-process lock) and needs no
   ``close()``. It behaves like a read-only array: ``shape``, ``dtype``, ``ndim``
   and numpy-style slicing, so ``dask.array.from_array`` accepts it directly.

   Files are opened without HDF5 file locking, so do not read a file that is still
   being written. On NFS, locking made reads 1.5x slower, and 3x when the file was
   already cached (raw Luxendo tiles, 16 workers).

.. py:function:: connected_components(tiles: Sequence[zarrsmith.mosaic_manager.tile.Tile], tolerance: Optional[Sequence[float]] = None) -> List[int]

   Component index of every tile: tiles whose boxes overlap or touch are connected.

   Two tiles touch when their ``(z, y, x)`` boxes (:attr:`Tile.extent`) overlap or
   are less than ``tolerance`` apart on every axis (default: one voxel). Components
   are numbered by their position: by the ``y`` then ``x`` then ``z`` start of their
   bounding box, so the numbering does not depend on the tile order. A position
   counts once, where it is first seen, and its tiles at later timepoints share its
   component: stage drift over time neither joins nor splits fields.


.. py:function:: label_fields(tiles: Sequence[zarrsmith.mosaic_manager.tile.Tile], tolerance: Optional[Sequence[float]] = None) -> List[str]

   Set ``tile.field`` on every tile to the name of its connected component.

   Tiles that already have a field (given by the reader) keep it. Returns the
   field names in order. See :func:`connected_components`.


.. py:class:: MosaicManager(path: str | pathlib.Path)

   Bases: :py:obj:`abc.ABC`


   A set of separately acquired, positioned tiles (not yet one image).

   Unlike a :class:`~zarrsmith.microscope_manager.MicroscopeManager`, which wraps one
   image, a mosaic exposes the raw tiles lazily and fuses them on request with
   :meth:`fuse`. Subclasses implement :meth:`_scan` only.

   Mosaics can be used as context managers so that open file handles are closed::

       with mosaic_manager.LuxendoMosaicManager("raw_folder") as mosaic:
           mosaic.fuse("overview.ome.zarr", ds=(4, 8, 8), projection="max")

   When loaded, every tile is labelled with the **field** it belongs to: tiles
   whose boxes overlap or touch form one field (a connected component), named
   ``field0``, ``field1``, ... by position (see :attr:`fields`). :meth:`fuse`
   fuses the first field by default; pick another with
   ``mosaic.fuse(out, field="field1")``. Tiles of several fields are never fused
   together: that raises a :class:`~zarrsmith.mosaic_manager.fields.MultipleFieldsError`.

   A mosaic can hold several **timepoints** (:attr:`timepoints`): :attr:`tiles` then
   has the tiles of all of them. :meth:`fuse` places every timepoint with the geometry
   of one reference timepoint and :meth:`visualize` adds a time slider.

      ``(t, z, y, x)`` array of the tiles of one position over ``timepoints``, read lazily.

      The array covers every place the tile reaches, and every timepoint holds the tile
      at its own position, rounded to a voxel, with zeros around it (which read nothing).
      A timepoint without a tile, or whose tile has another shape than the earliest
      one, is shown as zeros.

      Returns the array, the position of its first voxel and, per timepoint with a tile,
      the ``(z, y, x)`` voxel where the tile starts.



   .. py:method:: contrast_limits(tiles: Optional[Sequence[zarrsmith.mosaic_manager.tile.Tile]] = None, n_tiles: int = 6, block: int = 64, percentiles: Tuple[float, float] = (0.5, 99.9)) -> Dict[str, Tuple[float, float]]

      Display range of every channel, estimated from a small sample.

      For each channel, one ``block``-sized cube is read from the centre of up to
      ``n_tiles`` tiles (about 0.5 MB each for uint16 and ``block=64``, the HDF5
      chunk size of Luxendo tiles), and the given percentiles of those voxels are
      returned as ``(low, high)``. The sampled tiles are the ones closest to the
      centre of each tile group (e.g. each illumination side), where the sample
      usually is; edge tiles often only show background. Only the earliest timepoint
      of every position is sampled.



   .. py:method:: visualize(tiles: Optional[Sequence[zarrsmith.mosaic_manager.tile.Tile]] = None, viewer: napari.Viewer | None = None, contrast_limits: str | Dict[str, Tuple[float, float]] | None = 'range')

      Show tiles in napari, each as its own layer at its stage position.

      One colour per channel and additive blending, so overlaps and gaps are
      easy to see. Data stays lazy: only the planes napari displays are read.
      All tiles of a channel share one contrast setting, and their layers are
      linked: changing the contrast or gamma of one tile changes all of them.

      When ``tiles`` span several timepoints, each position is one ``(t, z, y, x)``
      layer in which the tile sits at its stage position of that timepoint, rounded to
      a voxel, so it moves as the napari slider scrolls through time, starting on the
      first timepoint. The layer covers every place the tile reaches. Slider step ``i``
      is the ``i``-th of the timepoints shown. Only the planes displayed at the current
      timepoint are read.

      Parameters
      ----------
      tiles
          Tiles to show (default: all), e.g. ``mosaic.select(channel="cFos-647")``.
          Every displayed plane reads whole HDF5 chunks of every tile, so
          showing fewer tiles keeps napari responsive.
      viewer
          Viewer to add the layers to; a new one is created by default.
      contrast_limits
          ``"range"`` (default) uses the whole range of the data type (0 to
          65535 for uint16), which reads nothing: set the contrast of one tile
          and the linked tiles follow. ``"auto"`` estimates it per channel with
          :meth:`contrast_limits` (reads a small sample, slow on network drives);
          a ``{channel: (low, high)}`` dict uses those, with the whole range for
          the channels it leaves out; ``None`` lets napari compute them per
          tile (slow on large tiles).

.. py:function:: fuse_tiles(tiles: Sequence[zarrsmith.mosaic_manager.tile.Tile], out: str | pathlib.Path, *, ds: Sequence[int] = (1, 1, 1), projection: Optional[str] = None, blend: str = 'sigmoid', channels: Optional[Sequence[str]] = None, channel_names: Optional[Sequence[str]] = None, channel_colors: Optional[Sequence[str]] = None, crop: Optional[dict] = None, skip: Optional[Sequence[zarrsmith.mosaic_manager.tile.Tile]] = None, levels: int = 1, downscale_factor=2, workers: int = 1, executor: str = 'auto', out_dtype=None, midline_axis: Optional[str] = None, sigmoid_steepness: float = SIGMOID_STEEPNESS, timepoints: Optional[Sequence[int]] = None, reference_timepoint: Union[int, str, None] = None, overwrite: bool = False, name: Optional[str] = None, temp_dir: str | pathlib.Path | None = None, temp_compression: bool = False, progress: bool = True, transforms_path: str | pathlib.Path | bool | None = True, tile_id: Optional[Callable[[zarrsmith.mosaic_manager.tile.Tile], str]] = None, source: Optional[str] = None, **write_options)

   Fuse ``tiles`` into an OME-Zarr image and return it as a ``ZarrManager``.

   Parameters
   ----------
   tiles
       Tiles to fuse (all must share voxel size and unit).
   out
       Output ``.ome.zarr`` path.
   ds
       ``(z, y, x)`` integer downsampling factors applied while reading the tiles
       (each output voxel is the mean of its block).
   projection
       ``None`` for a 3D volume, ``"max"``/``"sum"`` for a 2D projection along z.
   blend
       How tiles that overlap are merged:

       * ``"sigmoid"`` (default) -- smooth transition: across an overlap, the
         share of each tile follows a sigmoid of the log ratio of the distances
         to the two tile borders, from 0 at a tile's border through 1/2 in the
         middle of the overlap to 1 at the other tile's border, so no seam is
         visible. The tiles of each ``group`` are fused separately, then the
         groups are merged the same way across their overlap along
         ``midline_axis`` (the switch is centred where ``"midline"`` cuts);
       * ``"max"`` -- keep the brighter value;
       * ``"sum"`` -- add the values, so overlaps show up as brighter bands;
       * ``"midline"`` -- ``max`` within each tile ``group``; where groups
         overlap, the image switches sharply from one group to the next at the
         middle of their overlap, along ``midline_axis``.

       Tiles of several **cameras** (``Tile.camera``, e.g. the opposing views of a
       MuVi SPIM) are blended like groups, one view per camera: the tiles of each
       camera are fused first, then the views are blended along ``midline_axis``
       (default ``z``, the detection axis), each camera on the side its
       ``attrs["detection_direction"]`` points to, where it images sharply. Tiles
       with several cameras and several groups are refused. Projections of several
       cameras are merged with the maximum (``projection="max"``) or the mean
       (``"sum"``) of the views. With ``"max"``/``"sum"`` the cameras are merged like
       any other tiles.
   channels
       Tile channels to fuse, in output order. Default: all, in tile order.
   channel_names, channel_colors
       Names and colours (hex or matplotlib names) written for the output
       channels. Default: the tile channel names and the ZarrSmith palette.
   crop
       Part of the output to write, in output voxels (after ``ds``), e.g.
       ``{"y": slice(100, 900), "z": slice(0, 50)}``. For projections, a ``z``
       crop limits the planes that are projected.
   skip
       Tiles to leave blank: they are not read, but the output keeps the size and
       position it has with them, so their area stays 0 (where no other tile
       covers it). With ``blend="midline"``/``"sigmoid"`` they still count for
       the position of the switch between groups.
   levels
       Number of pyramid levels.
   downscale_factor
       Factor between pyramid levels: one integer or ``(z, y, x)``.
   workers
       Number of regions fused in parallel (threads or processes, see ``executor``).
   executor
       ``"process"``, ``"thread"`` or ``"auto"`` (processes when ``workers > 1`` and
       every tile's data is picklable, e.g. :class:`~zarrsmith.mosaic_manager.H5Array`;
       threads otherwise). h5py serialises reads inside one process, so processes
       are what actually speeds up reading from HDF5 tiles.
   out_dtype
       Output dtype. Default: input dtype for ``sigmoid``/``max``/``midline``,
       ``float32`` for ``sum``.
   midline_axis
       ``"x"``, ``"y"`` or ``"z"``: axis along which groups (or cameras) are separated
       (``midline`` and ``sigmoid``). Default: ``"z"`` for the views of several cameras
       in 3D, ``"x"`` otherwise.
   sigmoid_steepness
       Steepness of the ``sigmoid`` transition (> 0). The share of a tile
       goes from 10% to 90% over the central ``1 - 2 / (1 + 9 ** (1 / s))``
       of the overlap: about 27% for the default 4, 14% for 8, 50% for 2.
   timepoints
       Timepoints to fuse (``Tile.timepoint`` values). Default: all. With more than
       one, the output has a leading ``t`` axis (``tczyx``, or ``tcyx`` for
       projections), in increasing order; with one, it has none.
   reference_timepoint
       Timepoint whose tiles set the geometry (output grid, tile offsets, transitions
       between tiles and groups); it need not be among ``timepoints``. Every timepoint
       is fused with this geometry, so ``crop``, tile selections and the output shape
       hold for all of them, and timepoints fused in separate runs line up. Default:
       the first timepoint of ``tiles``. Tiles are matched across timepoints with
       :func:`~zarrsmith.mosaic_manager.tile.series_keys`. A tile missing at a timepoint
       stays blank there (with a warning), a tile without a counterpart at the reference
       is not fused (with a warning), and a tile with another shape, voxel size or
       unit than its reference tile raises ``ValueError``.

       ``"all"`` places every timepoint at its own positions instead. The output grid
       covers the tiles of all timepoints of ``tiles``, also those not in ``timepoints``,
       so ``crop`` and the output shape hold for all of them and timepoints fused in
       separate runs line up. Tile offsets and transitions are computed for each
       timepoint, so tiles and the overlaps between them follow the reported positions.
       A tile missing at a timepoint stays blank there (with a warning).
   overwrite
       Replace ``out`` if it is an existing Zarr store (with a warning, once the
       fusion has succeeded). Otherwise an existing non-empty ``out`` raises
       ``FileExistsError``.
   name
       Image name stored in the metadata.
   temp_dir
       Folder for the temporary fused level 0 (deleted at the end). Default:
       next to ``out``. A local disk is faster when ``out`` is on a network share.
   temp_compression
       Compress the temporary level 0. Off by default: skipping compression (and
       decoding it again for the pyramid) is noticeably faster, but the temporary
       store then takes the full uncompressed size of level 0 (``plan_fusion(...).nbytes``),
       so ``temp_dir`` needs room for it. Turn it on when disk space is short.
   transforms_path
       Where to write the transforms of the fusion (JSON, see :func:`transforms_document`):
       the position and flips of every fused tile at every timepoint, before anything
       is fused. ``True`` (default): next to ``out``, see :func:`default_transforms_path`;
       ``False``/``None``: not written. Load it back with
       :meth:`MosaicManager.apply_transforms <zarrsmith.mosaic_manager.MosaicManager.apply_transforms>`.
   tile_id, source
       Name of every tile in the transforms (default: ``channel/stack[/camera]``) and
       the mosaic they come from; :meth:`MosaicManager.fuse` sets both.
   progress
       Show progress bars.
   **write_options
       Any other :meth:`~zarrsmith.microscope_manager.MicroscopeManager.to_zarr`
       option, as for ``zarrsmith convert``: ``chunks``, ``shards``, ``shard_target_mb``,
       ``shard_exclude_axes``, ``zarr_format``, ``ngff_version``, ``compressor``,
       ``compressor_level``, ``drop_singleton``, ``num_workers``, ``storage_options``.
       ``chunks`` is given in the output axis order (``c, z, y, x``, or ``c, y, x``
       for projections, after a leading ``t`` for several timepoints).

   The display window of every channel (OMERO ``window`` metadata) is set to the
   0.5th-99.9th percentile of the fused values of all timepoints, ignoring blank
   areas, so viewers open the result with a usable contrast; see :func:`display_windows`.

   When ``tiles`` hold several timepoints, the root attribute ``zarrsmith_fusion``
   records the acquired timepoints of the output's ``t`` axis and the reference.

   Use :func:`plan_fusion` with the same arguments to get the output shape and
   size without reading or writing anything.

   ``tiles`` must come from one field (``Tile.field``, set by
   :class:`~zarrsmith.mosaic_manager.MosaicManager`; skipped tiles count): tiles of
   separate fields are not fused, a
   :class:`~zarrsmith.mosaic_manager.fields.MultipleFieldsError` is raised before
   anything is read or written.

.. py:class:: OperaFlatfield(mean: float, coefficients, dims=None, origin=None, scale=None)

   Harmony's background flat-field correction of one channel (picklable).

   Harmony describes the uneven background of a channel as a 2D polynomial ``P``,
   normalised to a mean of 1, and its mean level ``Mean`` (``FlatfieldProfile`` of
   the index, ``Background`` entry). It corrects every plane with::

       raw >= Mean * P :  raw - Mean * (P - 1)    (above the background: remove its unevenness)
       raw <  Mean * P :  raw / P                 (below it: rescale it to the flat level)

   Both branches give ``Mean`` at ``raw = Mean * P``. This reproduces the images
   stitched by Harmony to within rounding.

   ``P(u, v) = sum_k sum_i c[k][i] * u**(k - i) * v**i``, with ``u = (x - Origin[0]) * Scale[0]``
   along image columns and ``v = (y - Origin[1]) * Scale[1]`` along rows, in the
   pixels of a ``Dims`` image (rescaled to the image size, e.g. for another binning).
